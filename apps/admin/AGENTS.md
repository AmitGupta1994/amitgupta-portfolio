# Admin (Payload CMS) Agent Instructions

Payload CMS 3 running inside its own Next.js app on port 3001, backed by Postgres. It owns all portfolio content; `apps/frontend` reads it over the REST API.

## Layout

- `src/payload.config.ts` — registers collections and globals, Postgres adapter, `serverURL`.
- `src/collections/` — `Projects`, `Experiences`, `Expertise`, `SkillCategories`, `Publications`, plus `Media` (uploads) and `Users` (admin auth).
- `src/globals/` — singletons: `Profile`, `Navigation`.
- `src/app/(payload)/` — generated by Payload; don't hand-edit. Regenerate `admin/importMap.js` with `npm run generate:importmap -w admin` after adding custom admin components.
- `src/seed/` — `data.ts` is the initial content; `npm run seed -w admin` replaces all portfolio content with it (users and media untouched).

## Conventions

- Every content collection/global uses `publicRead` access and the `revalidateFrontend` hooks, so saves refresh the frontend. Pass `context: { disableRevalidate: true }` for bulk local-API writes.
- List collections carry the shared `orderField` and `defaultSort: 'order'` (skill categories sort by `priority`).
- When a field changes shape, update the matching mapper in `apps/frontend/src/data/` and run `npm run generate:types -w admin`.
- In development the Postgres adapter pushes schema changes automatically. Before deploying, create migrations with `npm run payload -w admin -- migrate:create`.

## Environment

Copy `.env.example` to `.env`. `REVALIDATE_SECRET` must match the frontend's.
